# 指标与日期语义

## 指标

| 自然语言 | `metric` | 含义 |
| --- | --- | --- |
| 新增用户、安装用户 | `new` | 查询周期内首次安装或新增的用户 |
| 活跃用户 | `active` | 查询周期内发生过活跃行为的用户 |
| 启动次数 | `start` | 查询周期内应用启动次数 |
| 累计用户、总用户 | `total` | 截至时间点累计的用户量，仅用于用户趋势 |
| 平均使用时长 | `avgDuration` | 人均或接口定义的平均使用时长，仅用于用户趋势 |
| 平均使用频次 | `avgFrequency` | 人均或接口定义的平均启动频次，仅用于用户趋势 |

不要将“用户数”和“启动次数”混为一谈。平均时长的单位、平均频次的计算口径以 CLI 返回字段为准；响应未提供单位时不要猜测。

## 查询类型边界

- 今日总体数据使用 `statistics.today`。
- 今日逐小时走势及昨日、七日前同时间对比使用 `statistics.period`。
- 昨日活跃、周活跃、月活跃和 DAU/MAU 使用 `statistics.activity`。
- 任意合规日期范围内的新增、活跃、启动、累计、平均时长或平均频次走势使用 `statistics.userTrend`。
- 留存 cohort 使用 `statistics.retention`。返回包含次日至第 7 日以及第 30 日留存字段，不把用户所问窗口误当成请求参数。

## 日期规则

所有自然语言日期按 `Asia/Shanghai` 的自然日解释，再转换成 `YYYY-MM-DD`。

- 今天：上海时区当前自然日。
- 昨天：今天前一个自然日。
- 最近 N 天（非留存）：今天之前的 N 个完整自然日，不包含今天。
- 明确起止日期：包含起始日和结束日。

例：当前日期为 `2026-08-13` 时，“最近 7 天用户趋势”是 `2026-08-06` 至 `2026-08-12`。

## 留存数据成熟度

留存的 cohort 结束日期最晚为上海时区的前天，即当前自然日减 2 天。昨天的次日留存需要今天结束后才完整形成，因此昨天和今天都不能作为留存 `endDate`。

- “最近 N 天留存”：以前天为 `endDate`，再向前取 N-1 个自然日作为 `startDate`。
- 明确日期范围：保留用户输入；若 `endDate` 晚于前天，直接拒绝，不自动改成前天。
- 拒绝时说明实际结束日期、当前最晚可查询日期，以及数据需要等待次日完整形成。
- `new`、`active`、`start` 三种留存口径使用相同成熟度规则。

例：当前日期为 `2026-08-13` 时，留存最晚日期为 `2026-08-11`，“最近 7 天留存”是 `2026-08-05` 至 `2026-08-11`。

调用趋势或留存前检查：

- `startDate` 不晚于 `endDate`。
- `statistics.retention` 的 `endDate` 不晚于上海时区前天。
- `statistics.retention` 按包含首尾的自然日数量计算，最多 30 天；天数等于结束日期与开始日期的自然日差加 1。
- `statistics.userTrend` 最多 90 天。
- 日期必须位于最近一年内。
- `endDate` 不得晚于今天。

不满足约束时不要调用 CLI，明确指出哪条约束不满足。

边界示例：

- `2026-07-01` 至 `2026-07-30` 包含 30 个自然日，允许查询留存。
- `2026-07-01` 至 `2026-07-31` 包含 31 个自然日，拒绝查询留存，并提示缩短范围或拆分查询。
- 合法的 31 至 90 天范围仍可用于 `statistics.userTrend`。

## 默认口径

- 留存未说明用户类型时，使用 `metric: "new"`，并在结果前说明“按新增用户留存查询”。
- 活跃范围未说明时，不传 `activityScope`，由 CLI 和接口采用默认的前台活跃口径；结果中说明这一默认值。
- 用户明确要求包含后台活跃时，传 `activityScope: "all"`。
- 除上述两项外，不自行猜测缺失的指标、日期或维度含义。

## 结果解释

- `null`、缺失字段或空数组表示接口未返回可用数据，不等于数值 `0`。
- 数值 `0` 可以如实表述为零。
- 留存日期较近、对应窗口尚未形成时，说明留存数据尚未成熟。
- 百分比按 CLI 标准化字段的实际值展示；不要自行乘除 100 或改变精度。
- 摘要只描述数值、方向和查询口径，不推断变化的业务原因。
